# 产品边界

## 产品定位

Agentic GenBI 是面向公司内部业务人员的智能 BI 平台。用户通过持续自然语言对话提出分析需求，系统在受控数据范围内理解业务语义、规划查询、生成并执行 SQL、校验结果，并返回可核对的表格、图表、SQL、结论和警告。

目标体验是：

```text
持续对话
→ 理解业务需求与语义口径
→ 制定查询计划
→ 生成、校验并执行 SQL
→ 校验和必要时修复结果
→ 生成表格、图表与分析结论
→ 保存为分析资产
→ 分享、刷新、版本化
→ 固定到个人或团队仪表板
```

产品能力的实际完成状态以 [`../plans/current.md`](../plans/current.md) 为准。本文中的目标边界不等于已经实现或已经排期。

## 已确认的长期产品边界

- 面向公司内部使用，支持多个本地用户，但不做多租户产品。
- 使用飞书 OAuth 登录；飞书负责身份认证，不同步飞书组织架构，团队和系统权限在应用内部维护。
- 支持个人分析空间、个人仪表板、内部团队和团队仪表板。
- 业务数据源目标支持 MySQL、Doris 和 SQL Server；保留未来跨数据源分析的扩展边界。
- OpenAI Agents SDK 主导分析过程；Agent 负责理解、规划、工具选择和结果组织，不负责认证、授权或绕过查询安全层。
- 普通用户可以查看系统生成的 SQL；高级用户可以修改和重新执行 SQL，但修改后的 SQL 仍必须经过完整权限与安全校验。
- 分析结果目标支持保存、分享、手动刷新和版本管理；暂不做定时刷新和通用任务调度。
- 图表以稳定的 `ChartSpec` 作为中间协议，目标由 ECharts 在前端渲染；Agent 不直接输出完整 ECharts `option`。

## 当前已交付能力

- 飞书 OAuth 登录、后端 Cookie 会话、当前用户查询、退出和独立登录页；过期会话会被拒绝并清理。
- 自然语言分析请求通过 OpenAI Agents SDK 转换为受控的只读 MySQL 查询。
- SQLGlot AST 校验、只读单语句约束、最大返回行数、查询超时、工具调用上限和有限 SQL 自动修复。
- 返回公开执行步骤、SQL、结构化表格、图表描述信息、结论与警告。
- 分析任务持久化到应用状态 MySQL，并绑定当前用户；未登录请求被拒绝，管理员可读取全部任务，普通用户越权读取统一返回不存在。
- 服务重启后可以从应用状态库读取已持久化的任务结果。

当前实现仍是单次问题驱动的分析任务，不等同于已经具备持续会话、语义模型、ECharts 渲染、分析资产、分享或仪表板。

## 第一阶段目标闭环

第一阶段围绕公司内部单数据源分析形成完整闭环，按独立可验证的小切片交付：

1. 飞书登录与多用户任务隔离。
2. 持续会话、消息记录与可恢复的分析状态。
3. 基础语义模型：模型、指标、维度、字段说明和表关联关系。
4. 结构化 `SemanticIntent` 与 `QueryPlan`，再生成数据库方言 SQL。
5. SQL 安全校验、权限校验、只读执行、有限自动修复和结果校验。
6. 表格、`ChartSpec`、ECharts 图表、SQL 与分析结论展示。
7. 将用户确认的结果保存为分析资产，并支持手动刷新和版本记录。

第一阶段优先使用一个主 Agent 加多个受控工具，不以多 Agent 拆分作为目标。

## 目标产品模块

### 会话与分析

- `Conversation` 表示一次持续分析会话，包含消息、当前分析状态和多次 `Analysis Run`。
- `Analysis Run` 表示会话中的一次执行，记录用户输入、语义理解、查询计划、SQL、工具调用、结果、图表、结论、错误、重试和耗时。
- 用户追问应基于当前分析状态增量修改：数据范围变化回到查询规划阶段，纯图表变化只回到图表规划阶段。

### 图表策略

- 图表是分析结果的第一类产物，不是装饰。表格里已经能读出数字，但**用户期望每次多行分析都附带图表**作为视觉锚点。
- 适用规则：查询结果 ≥ 2 行且至少有一列数值 → 必出图；单行聚合（如"昨日 GMV 总额"）可省。
- 图表类型由后端兜底默认 + Agent 自选两层构成：Agent 主动出图时优先使用 Agent 决策；Agent 漏出图时后端从 `table.columns` 中按"第一非数字列 + 第一数字列"自动生成柱状图。
- 视觉规范遵循 `docs/design/design-system.md`：coral / ink / line / muted 调色板。

### 分析资产

- `Analysis Artifact` 是用户确认并保存的结果，与对话过程分离。
- 资产保存原始问题、查询计划、SQL、结果快照、`ChartSpec`、结论、数据源引用和语义模型版本。
- 修改筛选、修改图表、刷新数据均产生新版本；历史版本保留当时结果快照。
- 默认刷新优先复用上次 SQL，重新校验权限和安全；失败时才允许 Agent 重新规划。

### 仪表板与分享

- 仪表板分为个人仪表板和团队仪表板。
- 仪表板卡片引用分析资产及指定版本，不复制 SQL 和完整分析逻辑。
- 分享权限目标包括查看、刷新、编辑和再分享，具体授权模型按后续切片逐步实现。

### 团队与角色

- 系统管理员在应用内部创建团队并指定团队管理员。
- 目标团队角色为 `team_admin`、`team_editor` 和 `team_member`。
- 目标系统角色为普通用户、高级用户和系统管理员。
- 角色是功能权限的基础，但数据源、模型、指标、字段和数据范围权限仍由后端独立执行。

## 当前阶段非目标

- 多租户隔离、外部客户门户和跨租户共享。
- 飞书组织架构同步。
- 多 Agent 编排。
- 应用层跨数据源 Join；仅保留未来 `FederatedQueryPlanner` 的架构边界。
- 定时刷新、通用任务调度、可靠队列、告警中心和审批流。
- 公司级公共仪表板。
- Kubernetes、微服务拆分和为尚未出现的规模问题预先引入 Redis。
- 复杂指标版本、数据血缘和复杂字段级权限配置后台。

## 业务原则

- **可解释性优先**：结果必须包含足以核对的 SQL、数据和公开执行信息。
- **Agent 主导分析，不主导安全**：Agent 决定如何分析，系统决定允许做什么。
- **统一业务口径**：核心指标来自语义模型，Agent 不临时发明指标公式。
- **受控 SQL 执行**：Agent 和高级用户都不能绕过查询网关。
- **会话与资产分离**：会话保存探索过程，资产保存用户确认的可复用结果。
- **小步交付**：每项能力拆成可独立验证的最小垂直切片，不一次性实现完整目标架构。
- **反馈驱动**：产品边界变化时更新本文档，具体实施与验证事实更新 `plans/current.md`。
