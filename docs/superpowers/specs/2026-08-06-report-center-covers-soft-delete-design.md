# Report Center Covers and Soft Delete Design

## Goal

把报表中心改成多列 PDF 封面式卡片。卡片使用现有 Report JSON 绘制不查询数据的结构蓝图；点击卡片主体才打开完整 Report。与此同时，把当前占位的删除操作接入后端，并改为无回收站入口的软删除。

## Scope

本次只修改 Report 中心卡片、轻量封面渲染、Report 删除链路及其必要的数据过滤。保留完整 Report 的 Puck、ECharts、VTable 和查询行为；保留 Report 分享权限和“新建会话”现有权限判断。

本次不做回收站、恢复、缩略图图片存储、截图服务、后台预渲染任务、数据缓存或无关页面重构，也不引入新依赖。

## Report Cover

新增前端 `ReportCover` 组件。它接收现有 `Report`，读取 `layout.content` 以及 `filters`、`charts`、`tables` 的引用关系，用 DOM、CSS 和少量内联 SVG 绘制结构蓝图。

封面只表示布局，不表示真实数据：

- 筛选组件显示为标签和输入框轮廓。
- 图表组件按 ECharts series 类型显示简化的柱、线、饼、雷达、仪表盘或漏斗轮廓；未知类型使用通用图表轮廓。
- 表格组件显示为表头和网格行。
- 标题、Markdown、指标或未知布局块显示为轻量文本/内容占位。
- 组件位置沿用 Report 的 12 栅格布局信息，使多栏 Report 在封面上仍然表现为多栏。

`ReportCover` 不挂载 `ReportProvider`、`ReportPanel`、ECharts 或 VTable，不调用查询接口，也不新增数据库字段。Report JSON 发生更新后，封面随列表返回的数据自然更新。

## Card Layout and Interaction

“我的 Report”和“分享给我”都固定使用 6 个等宽列，不根据视口或内容区宽度改变列数。单张卡片随列宽缩放并保持 3:4 竖向纸张比例，包含折角、结构蓝图、标题、摘要和更新时间；窄空间继续沿用现有文字截断，不新增横向滚动或另一套卡片形态。

- 点击卡片主体打开现有完整 Report 预览；此时才允许 Report 运行时执行真实查询。
- 移除单独的“预览”按钮。
- 鼠标悬停或键盘聚焦卡片时显示操作栏。
- 操作按钮必须阻止冒泡，不能同时触发卡片主体预览。
- 卡片主体可通过键盘触发，不能只依赖鼠标。
- “回到会话”始终显示。没有来源会话，或者来源会话已删除/无法加载时，提示“无关联会话或会话已经删除”。
- “新建会话”继续使用当前 Report 作为引用上下文，并保留共享权限为 `view` 时不可复用的现有产品行为。
- “删除”只出现在用户拥有的 Report 上；分享给我的 Report 不提供删除源 Report 的操作。

删除前显示页面内确认弹层，不使用浏览器系统弹窗。请求成功后，本地列表立即移除卡片；请求失败时保留卡片并显示错误提示。

## Soft Delete Contract

`reports` 表新增可空的 `deleted_at` 时间列。删除接口保持现有 `DELETE /api/reports/{report_id}` 路径和所有者校验，但把物理删除改为设置 `deleted_at`。

- 只有 `owner_id` 匹配的用户可以删除。
- 第一次删除写入当前时间并返回成功。
- 同一所有者重复删除保持幂等并返回成功。
- 不匹配的所有者或不存在的 Report 继续按不可删除处理，避免泄露对象是否存在。
- 不物理删除 Report，也不删除 `report_shares` 记录。

所有普通读取路径都必须排除 `deleted_at IS NOT NULL` 的 Report，包括按 ID 打开、按会话列出、所有者列表、分享列表和 Report 查询执行。已删除 Report 的详情、分享链接和查询入口均按不存在处理。

JSON 开发存储采用等价的 `deletedAt` 字段，并保持同样的读取过滤和幂等删除行为。

## Data and Query Flow

报表中心列表仍返回现有完整 Report JSON，因此封面不需要额外网络请求。列表加载不会因为 `ReportCover` 产生 SQL 或数据查询。

只有用户点击卡片主体并挂载现有完整 Report 预览后，`ReportProvider` 才执行 Report 查询。删除成功后的列表更新只修改报表中心本地状态，不重新加载或执行其他 Report。

## Error Handling

- 删除操作在确认前不发送请求。
- 删除失败时保留卡片，并显示可理解的错误消息。
- 无来源会话与来源会话已删除使用同一提示：“无关联会话或会话已经删除”。
- 封面遇到未知或不完整布局块时显示通用占位，不影响卡片其他内容，也不回退到完整 Report 渲染。

## Verification

后端测试覆盖 JSON Store 与 PostgreSQL Store 的软删除、所有者限制、幂等删除、列表过滤、详情不可访问、共享列表过滤和已删除 Report 不可执行查询。

前端 Vitest 覆盖：固定 6 列网格、卡片主体打开完整 Report、无独立预览按钮、封面不挂载真实图表/表格运行时、操作按钮不触发预览、无来源会话提示、页面内删除确认、成功/失败删除、共享卡片无删除操作以及多栏蓝图结构。

完成后运行相关后端 pytest、相关前端 Vitest、TypeScript 检查，并在构建后的服务中用内置浏览器确认多列卡片、悬停操作、完整预览、软删除和无额外查询行为。
